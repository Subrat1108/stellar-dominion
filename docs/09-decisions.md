| 2026-07-05 | **Autopilot orbital insertion is a SPIRAL: the scripted velocity blends radial-approach → orbit-tangent near arrival** (Exploration polish B tuning, Session 21) | The velocity-matched approach + overshoot cap made the ship **station-keep just outside the arrival radius and never cross it**, so the `dist ≤ arriveDist` trigger never fired — it hovered and never orbited. Flying straight to centre then snapping to a tangential orbit was also not seamless. Within 5×arriveDist the scripted velocity now blends from a body-velocity-matched radial approach into the orbit tangent (direction = `ORBIT_DIRECTION`), capped below 1 so some radial closing always remains (guaranteeing arrival), with a small capture band that hands to the analytic hold moving tangentially. Result: one continuous "slide into orbit", reliably, position + velocity continuous. Regression-tested (off-axis start → stable orbit min==max==rIns). |
| 2026-07-05 | **Orbit framing: a CLOSE large-body low orbit (insertion 2 R), body biased to the LEFT; slow (300 s) and reversed sweep** (Session 21 tuning) | Playtest: 4 R read as "looking at a planet from afar" (a small full disc — "can't be in orbit if I can see the whole planet"), and 1.2 R was a featureless wall. 2 R subtends ~60° — a large curved world you can't take in at once (genuine low-orbit feel); a left yaw bias keeps it clear of the right-side panel; `LOW_ORBIT_PERIOD_S 40→300` makes the sweep stately not spinny; `ORBIT_DIRECTION = -1` reverses a sweep that read "clockwise/backwards". All are exposed feel constants (subjective, tuned in-browser). |
| 2026-07-05 | **Autopilot approach is a two-phase, body-SCALED profile that velocity-matches the drifting target** (Session 21 tuning) | Honest scale makes this hard: the system spans ~700 u but a low orbit is ~0.03 u, so a single trapezoid can't be both fast across the system and slow enough to watch a tiny body grow — at cruise one tick dwarfs the arrival bubble. Fix: fast cruise, then a long body-scaled slow zone (`approachSpeed` in `math/flight.ts`) so the planet grows gradually over ~20 s. And the approach **matches the body's heliocentric velocity** (inner planets drift ~0.03 u/s, as fast as a slow approach, so an unmatched approach never caught them). |
| 2026-07-05 | **Any custom ShaderMaterial MUST include the `logdepthbuf` chunks** (the renderer uses `logarithmicDepthBuffer: true`) (Session 21) | The procedural planet shader looked translucent — you saw stars through it. Cause: it wrote LINEAR depth while every built-in material (star, ship, starfield, orbit lines) writes logarithmic depth automatically, so the planet lost the depth comparison against the distant starfield and failed to occlude it. Adding `#include <common>` + the `logdepthbuf_pars_*`/`logdepthbuf_*` chunks to the vertex+fragment shaders fixes it. **Standing rule:** every future custom shader in this project must include those chunks or it will render with wrong occlusion. |
| 2026-07-05 | **Planetary rings + a Kuiper belt are render-only instanced debris fields (no sim entities, no collision)** (Session 21) | To sell the sense of scale (tiny ship, huge worlds, "fly through the ice"), gas giants get an icy ring and the system gets an outer Kuiper belt as `THREE.InstancedMesh` fields (`render/debris-field.ts`) — one draw call each, cheap on integrated GPUs. | 2026-07-04 | **Orbital gravity added as the "middle rung": deterministic patched-conic, with a TUNED-μ scene-scale feel magnitude — revises the Session-10 "flight is pure arcade, no gravity"** (Exploration polish B, Session 21) | Flight gains real but bounded gravity: each body has a sphere of influence (SOI); inside it the ship feels `a = μ/r²` toward the body, outside all SOIs gravity is negligible (free arcade cruise). Orbit is a real stable state; leaving a deep well needs escape velocity `√(2μ/r)`. **Crucially μ is a gameplay constant, not `G·M`:** at Polish-A honest scale a low orbit sits at ~0.01 scene units, where literal-SI gravity is ~1e-8 u/s² — imperceptible, no well, free escape. So we keep the real patched-conic **structure** (SOI, `μ/r²`, `v_circ = √(μ/r)`, `v_esc`) and tune only the **magnitude** via `μ = ω²·r_ins³` from a target low-orbit period. This is the exact **sibling of the ship-is-an-avatar and orbital-time/orbit-rate decisions** — honest structure, avatar-scaled magnitude, because literal scale is an empty void. Determinism is preserved by three pure regimes: autopilot = scripted velocity (no gravity); analytic held orbit = position a pure fn of tick, with ω **derived from μ** so the held orbit is a true circular orbit (seamless autopilot→manual handoff, no fall-in); manual-inside-SOI = semi-implicit symplectic Euler on the fixed 1/60 tick. Escape velocity is emergent, not special-cased; drag (the auto-stop aid) applies only outside SOIs so releasing thrust near a body lets you coast/orbit. NOT n-body (per the standing Kepler/patched-conic constraint). Full rationale: `docs/planning/session-21.md`. |
| 2026-07-04 | **Control model split into SET COURSE / AUTOPILOT / LAND with MANUAL vs AUTOPILOT modes; thrust locked in autopilot** (Exploration polish B, Session 21) | Today's single command both marks a target and flies there, which removes agency and makes a "course direction indicator" impossible. Now **SET COURSE** only marks the target + draws the indicator (no motion); **AUTOPILOT** commits to fly it (trapezoidal accelerate→cruise→decelerate profile, orbit insertion on arrival) and **locks manual thrust** while engaged (leave it via the ✕ AUTOPILOT button, not by nudging a key — supersedes the old "any manual input cancels autopilot"); **LAND** unchanged; **ENTER ORBIT** (manual, near a body) triggers the same analytic insertion. This also gives the gravity model its clean regime seam (autopilot = scripted, manual = gravity). |
